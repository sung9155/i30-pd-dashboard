# 앱이 받는 차량 값 목록 (i30 PD)

대시보드 앱이 차에서 읽는 값을 한곳에 모은 표다. 새 화면을 만들 때 어떤 칸에 무엇을 넣을 수 있는지 고르는 용도로 쓴다.

- **번호**는 `shared/src/com/veloster/vehicle/Telemetry.java`의 `LABELS` 순서다. 화면 코드(`ClusterKit` 등)에서는 `v(번호)` 또는 `v(Telemetry.상수)`로 읽고, 값이 없으면 `NaN`이다.
- **상수**는 `Telemetry`의 이름이다. `—`는 상수 없이 번호로만 쓰는 값이다(예: `v(0)` rpm, `v(7)` 차속).
- 앱은 값을 **읽기만** 한다. 차에 아무것도 보내지 않는다(OBD는 읽기 요청만 보낸다).
- 이 문서와 코드가 다르면 코드가 맞다. CAN 프레임을 어떻게 찾았는지는 [`HSCAN_DECODE.md`](HSCAN_DECODE.md)에 있다.

## 출처와 파싱 표기

| 출처 | 경로 | 코드 | 파싱 표기 |
|---|---|---|---|
| **hscan** | 순정 `hscand`의 `@hscan_mux` 소켓(채널 `0xc7`). 내비가 이미 받는 CAN 프레임을 슬롯별로 그대로 담는다. 초당 8~25번 | `Telemetry.hscanPd(cid, 슬롯, b, now)` | `b0`~`b7` = 슬롯 데이터 바이트, `u16(b2)` = `b2 \| b3<<8` (리틀 엔디언), `b4.0` = b4의 bit0 |
| **OBD 01** | 엔진 ECU 표준 PID | `Telemetry.obd(pid, a, b, now)` | `A`, `B` = 응답 데이터 바이트 |
| **OBD 22** | 제조사 진단 mode 22 (DID). 엔진·TCU·BCM | `Telemetry.obd(did, d, now)` | `d[n]` = 응답 바이트 배열, `u16be(d,n)` = `d[n]<<8 \| d[n+1]` |
| **TM** | 순정 텔레매틱스 `tm_hscan_service` (블루링크 내비만 있음) 3초마다 | `TmHscan` → `Telemetry.tm()` | 바인더 트랜잭션 코드 |
| **계산** | 앱이 다른 값으로 계산 | | |

상태: ✅ 실차에서 값으로 확인 · ◐ 프레임은 맞지만 그 상황을 아직 못 봄(예: 문 열기) · △ 후보(값이 맞는지 확정 전) · ✕ i30 PD에서는 안 나옴

hscan 슬롯 이름(EMS11, CLU11 …)은 공개 DBC(commaai/opendbc `hyundai_2015_ccan.dbc`)의 메시지 이름이다.

## 찾아봤지만 없는 값

- **유압(오일 압력), 수압(냉각수 압력):** 센서도 CAN 신호도 없다.
- **미션유 온도, 터빈 rpm:** TCU 프레임의 해당 바이트가 늘 0이다.
- **운전석 안전벨트, 뒷문 2개:** 대응하는 바이트나 슬롯을 못 찾았다.
- **오토홀드, 경사로 밀림 방지:** 아직 못 찾았다. 찾는 방법은 [`HSCAN_DECODE.md`](HSCAN_DECODE.md)의 "미확정" 절에 있다.
